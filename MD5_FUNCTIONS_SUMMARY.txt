⭐ FUNCIONES PRINCIPALES
================================================================================

1. md5hash(B, A, E, C)
   ├─ Propósito: Cifrar contraseña y rellenar campos ocultos del formulario
   ├─ Parámetros:
   │  ├─ B: Input de contraseña (vb_login_password)
   │  ├─ A: Campo oculto vb_login_md5password
   │  ├─ E: Campo oculto vb_login_md5password_utf
   │  └─ C: Flag para limpiar contraseña original
   ├─ Retorna: true
   └─ Ubicación: Scripts inline de la página

2. hex_md5(A)
   ├─ Propósito: Convertir texto a hash MD5 hexadecimal
   ├─ Parámetro: A (string) - Texto a cifrar
   ├─ Retorna: String con hash MD5 (hexadecimal)
   └─ Usado por: md5hash() internamente

3. core_md5(K, F)
   ├─ Propósito: Algoritmo core del cálculo MD5
   ├─ Parámetros:
   │  ├─ K: Array de palabras binarias
   │  └─ F: Longitud en bits
   ├─ Retorna: Hash MD5 en formato binario
   └─ Usa: Funciones auxiliares (md5_ff, md5_gg, md5_hh, md5_ii)

🔄 FLUJO DE AUTENTICACIÓN
================================================================================

PASO 1: Usuario ingresa credenciales
        └─ vb_login_username = "usuario"
        └─ vb_login_password = "contraseña_plana"

PASO 2: Al enviar formulario, se ejecuta md5hash()
        ├─ Obtiene valor de vb_login_password
        ├─ Calcula: hex_md5(str_to_ent(trim(contraseña)))
        └─ Obtiene hash MD5

PASO 3: Se rellenan campos ocultos
        ├─ vb_login_md5password = "{hash_md5}"
        └─ vb_login_md5password_utf = "{hash_alternativo}"

PASO 4: Se limpia el campo de contraseña (opcional)
        └─ vb_login_password.value = ""

PASO 5: Se envía formulario al servidor
        ├─ Contenido:
        │  ├─ vb_login_username: "usuario"
        │  ├─ vb_login_md5password: "5f4dcc3b5aa765d61d8327deb882cf99"
        │  └─ vb_login_md5password_utf: (valor similar)
        │
        └─ NOTA: La contraseña plana NO se envía al servidor

PASO 6: Servidor verifica el hash
        ├─ Lee vb_login_md5password
        ├─ Lo compara con el hash almacenado en BD
        └─ Otorga o deniega acceso

================================================================================
🛡️ ANÁLISIS DE SEGURIDAD
================================================================================

FORTALEZAS:
  ✅ Hash cliente-side (evita transmisión de contraseña plana)
  ✅ Limpieza de contraseña en memoria del navegador
  ✅ Soporte UTF-8 (hash alternativo)
  ✅ Verificación de navegador Mozilla

DEBILIDADES:
  ❌ MD5 es criptográficamente débil
  ❌ Vulnerable a colisiones de hash
  ❌ Sin salt en cliente (vulnerable a rainbow tables)
  ⚠️ Requiere HTTPS obligatorio
  ⚠️ Sin protección CSRF visible
  ⚠️ Sin rate limiting aparente

RECOMENDACIONES:
  🔒 Usar HTTPS para todo
  🔒 Migrar a SHA-256 o superior
  🔒 Implementar salt en servidor
  🔒 Agregar rate limiting en servidor
  🔒 Implementar CSRF tokens
  🔒 Considerar OAuth2/OpenID Connect
